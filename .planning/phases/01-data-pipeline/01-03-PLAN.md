<objective>
Implement the Zod v4 validation/transform layer for both raw CFBD `Team` and `Game` records via RED-GREEN-REFACTOR: a required-vs-nullable field split that drives D-09's hard-fail behavior, and a verbatim pass-through for `conferenceGame`/`seasonType` that satisfies DATA-06/DATA-07's "never re-derive" constraint by construction.

Purpose: This is the single validation boundary between CFBD's raw, mostly-nullable API response and every committed JSON file in this phase. Getting the required/nullable split wrong either crashes downstream on a null, or silently lets bad data through; getting the pass-through wrong quietly corrupts the one flag (`conferenceGame`) every later phase (standings, tiebreakers) trusts unconditionally.
Output: `scripts/lib/schemas.ts` exporting `RawTeamSchema`, `RequiredTeamFieldsSchema`, `transformTeam`, `reportRequiredFieldFailures`, `RawGameSchema`, `transformGame`, fully covered by `tests/schemas.test.ts`.
</objective>
