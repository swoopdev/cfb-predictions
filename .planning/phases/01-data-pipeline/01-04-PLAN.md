<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|--------------|
| CFBD API `logos[]` URLs -> outbound `fetch` | A logo URL sourced from an external API response is untrusted input before this module validates and fetches it |
| This module's output -> `public/logos/` on disk | Filenames written here become static assets served to every future browser session |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-01 | Tampering / SSRF | `vendorLogo`'s handling of a compromised or unexpected `logos[]` URL | high | mitigate | `vendorLogo` rejects any URL not starting with `https:` before attempting a fetch, as defense-in-depth even though CFBD is a trusted first-party source in this design (RESEARCH.md Security Domain). Enforced by this task's grep gate. |
| T-01-03 | Tampering | Path traversal via a crafted school/mascot name used as a filename | high | mitigate | Logo filenames are derived exclusively from CFBD's numeric `teamId`, never from `school`/`mascot` strings, closing this class of issue by construction. |
| T-01-02 | Information Disclosure | `CFBD_API_KEY` leaking into `coverage.json` or console output from this module | medium | mitigate | `coverage.ts` never reads `process.env`; enforced by this task's grep gate and the `JSON.stringify` secret-hygiene test case. |
</threat_model>
