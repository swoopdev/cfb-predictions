| Property | Value |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside badges, inline metadata |
| sm | 8px | Compact spacing: badge internal padding, gap between team rows inside a card |
| md | 16px | Default element spacing: game-card grid gutter (row and column gap), gap between filter controls |
| lg | 24px | Section padding: page horizontal padding (mobile), gap between the week-nav bar and the card grid |
| xl | 32px | Layout gaps: page horizontal padding (desktop ≥1024px), vertical gap between one conference group and the next within a week |
| 2xl | 48px | Major section breaks: gap above/below the empty-state block |
| 3xl | 64px | Page-level spacing: not used in Phase 2 (no long-form marketing content) |

Exceptions:
- Icon-only nav controls (prev/next week buttons) use a minimum 44×44px tap target regardless of visual icon size (Nuxt UI `UButton` `size="lg"` with `square`), to meet touch-target minimums — the icon glyph itself stays at the standard 20px, only the hit area is padded out.
- Game card grid: `repeat(auto-fill, minmax(280px, 1fr))`, 16px gap, so a single filtered result (zero-one-many case) renders as one natural-width card rather than stretching full-bleed.
- Responsive page gutters: 24px (`lg`) below 1024px, 32px (`xl`) at 1024px and above. No additional breakpoint-specific token is introduced.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 600 (semibold) | 1.2 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Usage mapping for this phase:
- **Body (14/400/1.5):** team names on game cards, filter control labels, footer text.
- **Label (12/600/1.2, uppercase, letter-spacing wide):** `neutral site` / `conference game` badges, conference group headers within a week ("SEC", "Big Ten", …), the "Week {n}" eyebrow above the page heading if used.
- **Heading (20/600/1.2):** page title, e.g. "Week 3".
- **Display (28/600/1.2):** empty-state heading only (e.g. "No games this week") — the single largest text on any Phase 2 screen; do not use it for anything else.

Exactly 2 weights are declared (400, 600) — do not introduce a third weight (e.g. bold 700) anywhere in this phase.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Nuxt UI `bg-default` (neutral "slate" scale — white / `slate-950` in dark mode, per `app.config.ts`) | Page background behind the entire slate view |
| Secondary (30%) | Nuxt UI `bg-elevated` / `bg-muted` (slate-50/100 light, slate-900/800 dark) | `UCard` surfaces (game cards), conference group header band, sticky week-nav bar background |
| Accent (10%) | Nuxt UI `primary` = green (`app.config.ts` `ui.colors.primary: 'green'`, tokens already defined in `main.css`) | See "Accent reserved for" below |
| Destructive | Nuxt UI `error` = red (Nuxt UI default semantic red) | Reserved for future phases (Phase 4 season-wide clear-picks confirmation, Phase 7 scenario delete). **Not used anywhere in Phase 2** — this phase has no destructive action (SLATE requirements are read-only). |

Accent reserved for:
- The currently-selected conference filter chip / currently-selected team in the combobox (active/pressed state)
- The currently-active week in the week-picker dropdown (current selection indicator)
- Focus rings on all interactive controls (prev/next buttons, filter dropdown, combobox, week picker) — accessibility requirement, not decorative
- The fill/border of the "conference game" badge specifically (the "neutral site" badge stays neutral-gray to keep only one badge type competing for accent attention per card)

Accent is explicitly **not** used for: team logos or any team-color rendering (those are data content, governed by each team's own `color`/`alternateColor` from `teams.json`, not app chrome — per PROJECT.md's "team color used sparingly as accents on picked winners," which doesn't begin until Phase 4's picking UI), the FCS-opponent placeholder shield, or default/unselected filter and nav states.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | This phase has no transactional CTA (read-only browse). The closest analog is week navigation: buttons are labeled "Previous week" / "Next week" (icon + `aria-label`, not a bare arrow with no label), and the week picker's placeholder reads "Jump to week…" |
| Empty state heading (week has zero games, e.g. week 14) | "No games this week" |
| Empty state body (week has zero games) | "Week {n} has no games in the 2026 schedule. Try another week." |
| Empty state heading (filter narrows a week to zero games, e.g. a team's bye week) | "No games match this filter" |
| Empty state body (filtered to zero games) | "{Team name} has no games in Week {n}. Clear the filter or pick another week." |
| Empty state (team combobox, no search matches) | "No teams found" (shown inside the combobox dropdown, no separate body copy needed — matches Nuxt UI `UInputMenu` empty slot pattern) |
| Error state | Heading: "Couldn't load the schedule." Body: "Something went wrong loading this season's data. Refresh the page — if the problem continues, the schedule data may be missing from this deploy." (No retry-fetch button: this is static JSON shipped with the build, not a flaky network call, so "refresh" is the only real recovery path — do not word this like a transient network error.) |
| Destructive confirmation | Not applicable in Phase 2 — no destructive actions exist yet (introduced in Phase 4 bulk-clear and Phase 7 scenario delete). |

## UI Considerations

> Populated by the ui-phase UI-consideration probe (Step 9.5) and lifted by plan-phase's
> `## UI Considerations` lift rule via the identical rule as SPEC `## Edge Coverage`. Shape-rooted UI *state*
> coverage (empty / loading / error / populated / partial / overflow / zero-one-many / long-text).
> Empty-state and error-state COPY live in `## Copywriting Contract` above — this section covers
> state coverage and REFERENCES those rows rather than restating the copy (de-dup).

Applicable state considerations resolved: 7 covered, 1 backstop, 0 unresolved

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | game grid (list-collection) — whole week empty | ✅ covered | Week with zero games (week 14) renders the "No games this week" empty state defined in Copywriting Contract; week picker still lists week 14 as selectable per CONTEXT.md D-15. |
| empty | game grid (list-collection) — filtered to zero games | ✅ covered | Conference/team filter narrowing a valid week to zero matching games (e.g. a team's bye week) renders the distinct "No games match this filter" empty state, not the week-empty copy — the two are worded differently so users don't confuse "empty week" with "empty filter result." |
| empty | team combobox (interactive-control / list-collection) — no search matches | ✅ covered | Combobox shows "No teams found" per Copywriting Contract; matches Nuxt UI `UInputMenu` built-in empty slot. |
| loading | game grid (list-collection) — initial `useGames()`/`useTeams()` resolution before first paint | 🧪 backstop | Skeleton grid (6 `USkeleton` placeholders shaped like `UCard`, no conference headers) shown only during the one-time initial data resolution. Subsequent week/filter changes are synchronous client-side operations against already-cached data (`staleTime: Infinity`), so no loading state is needed for week/filter switches — only initial app load. Backstop because the actual perceived duration depends on build/hosting behavior not yet measured. |
| error | game grid (list-collection) — `games.json`/`teams.json` fetch fails or is missing from the deploy | ✅ covered | Full-page error state per Copywriting Contract "Error state" row; no partial/broken card grid is ever shown. |
| populated | game grid (list-collection) — normal week, multiple conferences | ✅ covered | CONTEXT.md D-07's conference-grouped, alphabetically-sorted layout is the defined populated-state contract; typography Label role governs the group headers. |
| partial | game grid (list-collection) — FCS opponent not present in `teams.json` | ✅ covered | CONTEXT.md D-06: name-only text rendering (raw string from `games.json`) plus the same placeholder-shield fallback pattern established by Phase 1's `vendorLogo`/coverage report — not hidden or filtered. |
| long-text / overflow | game card team names (static-content) | ✅ covered | Team/mascot name truncates to a single line with ellipsis at card width; full name available via the native `title` attribute on hover/focus. Applies identically to real team names and to raw FCS-opponent name strings (D-06), since both render as plain text in the same slot. |
