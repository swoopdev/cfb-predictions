<task type="auto">
  <name>Task 2: Author usePicksStorage composable with localStorage persistence and corruption recovery (D-03, D-04, D-06, D-07, D-08)</name>
  <files>app/composables/usePicksStorage.ts</files>
  <action>
    Create a composable that wraps VueUse's `useStorage` (already auto-imported) to provide a reactive Ref for the picks object. Implement per RESEARCH.md Pattern 1:
    
    - Export a single function `usePicksStorage(season = 2026)` that returns a reactive `Ref<Record<number, number>>` (picks object: `{ gameId: winningTeamId, ... }`).
    - Storage key is season-namespaced: `cfb_picks_2026` (per D-06).
    - Initial value is empty object `{}`.
    - Implement a custom serializer (per VueUse's `serializer` option) with `read` and `write` functions:
      - `read`: Attempt `JSON.parse(v)`, validate that result is a plain object (not array, not null). If parse fails OR validation fails, silently:
        1. Preserve the corrupted string under `${key}_corrupt` key (per D-07)
        2. Log to console (debug only, no user-facing banner per D-08)
        3. Return empty object `{}`
      - `write`: Simply `JSON.stringify(v)` — no transformation needed.
    - Enable `mergeDefaults: true` so initial empty object is always available (even on first load).
    - VueUse will automatically handle `listenToStorageChanges` (cross-tab sync) — no additional configuration needed.
    
    Constraint: Do NOT use async/await; localStorage is synchronous. Do NOT call `localStorage.setItem` directly — VueUse's watch handler does this.
  </action>
  <verify>
    <automated>grep -c "useStorage" app/composables/usePicksStorage.ts && grep -c "cfb_picks_" app/composables/usePicksStorage.ts && grep -c "corrupt" app/composables/usePicksStorage.ts</automated>
  </verify>
  <done>Composable exists, uses `useStorage` for reactive persistence, implements corruption recovery with silent fallback to `{}`, preserves corrupted data under separate key, no user-facing errors on recovery</done>

      - `autoFilled: Ref<number[]>` — the array stored under `cfb_autofilled_2026`

    - Initial value: empty array `[]`.

    - Use a computed to convert the array to a Set for efficient lookups (Pattern 2).
    
    Rationale: Picks object is flat for JSON compactness (Phase 8 share links); provenance lives separately to avoid widening every pick record.

|----------|-------------|
| localStorage ↔ App | Untrusted input: user can manually edit localStorage in DevTools; corrupt JSON can be written; malformed picks object can be injected |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-04-01 | Tampering | usePicksStorage serializer | Medium | Mitigate | Wrap JSON.parse in try/catch; reject invalid picks gracefully (reset to `{}`, preserve original under `_corrupt` key); do NOT crash or expose error to user (D-07/D-08) |
| T-04-02 | Tampering | picks object shape | Low | Mitigate | Validate that parsed value is a plain object (not array, not null) before accepting; silently reject if shape invalid |
| T-04-03 | Denial of Service | localStorage quota | Low | Accept | For v1 (single season), 20 KB JSON + 888-element provenance array ≈ negligible quota. Revisit in Phase 7 (scenarios) if users accumulate many scenarios. No quota check needed now. |
| T-04-04 | Information Disclosure | localStorage data at rest | Low | Accept | Picks are speculative forecasts, not secrets. localStorage is unencrypted but lives in browser origin; no more or less exposed than other client state. No encryption/obfuscation needed. |
