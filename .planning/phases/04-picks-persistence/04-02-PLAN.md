  <name>Task 1: Implement team-color contrast validation utility (UI-SPEC: Team Color Contrast Handling)</name>
  <files>app/utils/teamContrast.ts, tests/utils/teamContrast.test.ts</files>
  <behavior>
    - Function `validateTeamContrast(color: string, mode: 'light' | 'dark'): { valid: boolean, filter?: string }` checks if a team color meets WCAG AA 4.5:1 contrast ratio against the card background (light mode: white/slate-50; dark mode: slate-900).
    - If contrast passes (ratio >= 4.5:1), return `{ valid: true }`.
    - If contrast fails, return `{ valid: false, filter: 'opacity-75' }` or `{ valid: false, filter: 'brightness(0.75)' }` (whichever restores contrast better).
    - Function should handle edge cases: invalid hex colors, case-insensitivity (normalize to lowercase), missing # prefix.
    - Should work at component runtime: given a team's color string from teams.json, compute the correct CSS filter to apply.
  </behavior>
  <action>
    Create `app/utils/teamContrast.ts` with:
    - Helper function `hexToRgb(hex: string)` to convert hex color to RGB (handles 3-digit and 6-digit formats).
    - Helper function `getLuminance(r: number, g: number, b: number): number` to compute relative luminance per WCAG definition (https://www.w3.org/TR/WCAG20/#relativeluminancedef).
    - Helper function `getContrast(color1: string, color2: string): number` to compute contrast ratio between two hex colors.
    - Main function `validateTeamContrast(teamColor: string, mode: 'light' | 'dark'): { valid: boolean, filter?: string }` that:
      1. Normalizes the team color (lowercase, add # if missing)
      2. Gets the card background color for the mode (light: #ffffff, dark: #0f172a for slate-950)
      3. Computes contrast ratio
      4. If ratio >= 4.5, return `{ valid: true }`
      5. If ratio < 4.5, try common filters (opacity-75, brightness(0.75), brightness(0.85)) and pick the one that gets closest to 4.5:1
      6. Return the best filter found
    
    Per UI-SPEC, the plan is to call this during component rendering and apply the filter dynamically via `:style` binding. Implementation can defer build-time pre-computation — runtime validation is acceptable for v1.
  </action>

  </verify>
  <done>Contrast validation utility exists; tests pass for sample team colors (SEC, Big Ten, etc.) in both light and dark modes; utility returns appropriate CSS filters</done>

  <files>app/components/GameCard.vue, tests/components/GameCard.test.ts</files>
  <behavior>
    - Component accepts new prop: `picks: Ref<Record<number, number>>` (reactive picks object from parent).
    - Clicking either the home or away team row calls `togglePick(teamId)`.
    - `togglePick` mutates picks.value: if game.id is already in picks and points to that team, delete it; otherwise, set picks[game.id] = teamId.
    - Computed `isPicked` returns true if game.id is in picks.
    - Computed `pickedTeamId` returns the winning teamId for this game, or undefined if unpicked.
    - Visual feedback: Picked team row gets a 3px left border in the team's color (applying contrast filter if needed) + a checkmark icon (Lucide, size 16px, green).
    - Unpicked team row remains neutral (no border, no checkmark).
    - Hover state on unpicked team: background tints slightly, checkmark appears faintly (`opacity-0` → `opacity-100` on hover preview).
    - Keyboard support: `tabindex="0"` on team rows, `@keydown.enter` and `@keydown.space` call `togglePick`.
    - Accessibility: `aria-label` on team rows: "{Pick|Clear pick}: {Team Name}", dynamic based on picked state.
  </behavior>
  <action>
    Modify `app/components/GameCard.vue`:
    
    1. Update `<script setup>` to accept new prop:
       ```
       picks: Ref<Record<number, number>>
       ```
    
    2. Add computed properties:
       ```
       const isPicked = computed(() => props.game.id in props.picks.value)
       const pickedTeamId = computed(() => props.picks.value[props.game.id])
       const pickedTeam = computed(() => {
         if (!isPicked.value) return null
         return pickedTeamId.value === props.game.homeId ? home.value : away.value
       })
       ```
    
    3. Add `togglePick(teamId: number)` function:
       ```
       function togglePick(teamId: number) {
         if (pickedTeamId.value === teamId) {
           delete props.picks.value[props.game.id]
         } else {
           props.picks.value[props.game.id] = teamId
         }
       }
       ```
    
    4. Import `validateTeamContrast` from utils and use it:
       ```
       const homeContrast = computed(() => validateTeamContrast(home.value?.color ?? '#000000', isDark.value ? 'dark' : 'light'))
       const awayContrast = computed(() => validateTeamContrast(away.value?.color ?? '#000000', isDark.value ? 'dark' : 'light'))
       ```
       (Use Nuxt's `useColorMode()` to detect isDark.)
    
    5. Update template: Replace Phase 2's simple "Away @ Home" layout with clickable, picked-state-aware rows:
       - Away team row (on click, calls `togglePick(away.id)`):
         - `cursor-pointer user-select-none` on click
         - `:class="{ 'border-l-4': pickedTeamId === away.id }"` (conditional border)
         - `:style="pickedTeamId === away.id ? { borderColor: away.color, ...applyContrast(awayContrast) } : {}"` (team color + filter)
         - Conditional checkmark: `<UIcon v-if="pickedTeamId === away.id" name="lucide:check" class="size-4 text-green-600 shrink-0" />`
         - Placeholder div (size-4) when not picked (maintains alignment)
         - Keyboard support: `@keydown.enter`, `@keydown.space`, `tabindex="0"`
         - Accessible label: `:aria-label="pickedTeamId === away.id ? `Clear pick: ${away.school}` : `Pick ${away.school} over ${home?.school}`"`
       - Same structure for home team row (after "Away @ Home" layout)
       - Keep Phase 2's badge section (neutral-site, conference-game badges)
    
    Constraint: Do NOT use v-model binding (picks is already a Ref); directly mutate via `togglePick`.
  </action>
