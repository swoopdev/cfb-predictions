| Property | Value |

## Spacing Scale

Inherited from Phase 2, applied to Phase 4 UI elements. Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gap inside badges, gap between checkmark and team name |
| sm | 8px | Compact spacing: badge internal padding, gap between "picked" indicator and team text |
| md | 16px | Default element spacing: gap between game-card rows (home/away), gap between progress badge and week heading |
| lg | 24px | Section padding: unused in Phase 4 (inherits from Phase 2 card layout) |
| xl | 32px | Layout gaps: unused in Phase 4 |
| 2xl | 48px | Major section breaks: unused in Phase 4 |
| 3xl | 64px | Page-level spacing: unused in Phase 4 |

Exceptions:
- Progress badge inline with week heading: uses `md` (16px) gap to separate "Week N" text from the "X/Y" badge text
- Fill/Clear buttons (UButton `size="sm"`) placed inline with week heading: use `md` (16px) gap before first button
- Picked team indicator (checkmark icon): 16px icon size, placed left of team name with `xs` (4px) gutter
- Bulk operation buttons sit at the end of the week heading row; when multiple buttons present (Fill + Clear), use `sm` (8px) gap between them

## Typography

Inherited from Phase 2. Phase 4 reuses all 4 typographic roles without introducing new sizes or weights:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 (regular) | 1.5 |
| Label | 12px | 600 (semibold) | 1.2 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Usage mapping for Phase 4:
- **Body (14/400/1.5):** team names on game cards (both picked and unpicked state remain at this size)
- **Label (12/600/1.2):** progress badge text ("8/10 picked"), week section headings, button labels on Fill/Clear buttons
- **Heading (20/600/1.2):** "Week {n}" page title (inherited from Phase 2 if week-header exists)
- **Display (28/600/1.2):** not used in Phase 4

Exactly 2 weights remain (400, 600) — do not introduce a third weight anywhere in this phase.

## Color

Inherited from Phase 2 for dominant, secondary, and accent. Phase 4 introduces **team-color accent for picked winners only**.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Nuxt UI `bg-default` (white / `slate-950` in dark mode) | Page background, remains unchanged from Phase 2 |
| Secondary (30%) | Nuxt UI `bg-elevated` / `bg-muted` (slate-50/100 light, slate-900/800 dark) | `UCard` surfaces (game cards), remains unchanged from Phase 2 |
| Accent (10%) | Nuxt UI `primary` = green (`#00DC82` light, `#016538` dark per main.css) | Reserve for UI chrome: focus rings on buttons, active state of Fill/Clear buttons (when pressed/highlighted as context), confirmation modal destructive button (for "Clear Season" confirmation). **Not** used for the picked winner visual itself (see Team Color Accent below). |
| Team Color Accent | Team's `color` field from `teams.json` | **Picked winner indicator:** left border (3px) or subtle background tint on the picked team's row inside the game card. Applied **only** to the picked team; the unpicked opponent remains at neutral card styling. The accent communicates "this team is the pick." |
| Destructive | Nuxt UI `error` = red (Nuxt UI default semantic red) | "Clear Season" confirmation modal: the primary button text/fill. No destructive action elsewhere in Phase 4. |

**Accent (green) reserved for:**
- Active button state on Fill/Clear Week and Fill/Clear Season buttons (`:hover`, `:active`, or `aria-pressed="true"`)
- Focus rings on all interactive controls (buttons, clickable team rows) — accessibility requirement
- The primary/confirm button in the "Clear Season" confirmation modal
- Modal overlay/focus trap management

**Accent (green) is explicitly NOT used for:**
- The picked team highlight (that uses team color, per PROJECT.md's "team color used sparingly as accents on picked winners")
- Unpicked team rows or neutral states
- Progress badge background (use neutral `bg-muted` or keep as text-only)

**Team Color Contrast Handling:**
- Per PROJECT.md: "Contrast must hold up — many team colors fail against light or dark surfaces at small sizes"
- For the picked team's color accent (left border or tint), apply a **CSS filter or opacity adjustment** to ensure sufficient contrast in both light and dark modes
- Example approach: `border-l-4` using `opacity-75` or a `brightness()` CSS filter if the team color would fail WCAG AA contrast on the card background
- Document this constraint in the executor's plan: "Validate all 138 team colors at the chosen accent placement against both light and dark surfaces; if a team color fails contrast, apply `opacity-75` or `brightness(0.8)` to the accent"

## Pick Interaction & Feedback

### Click Target & States

**Unpicked state (neutral):**
- Entire game card is clickable per PICK-01 (click a team name/logo to pick)
- Home team row and away team row have `cursor: pointer` and `user-select: none` on the team name/logo section
- No background change on hover (Phase 2 cards already have subtle hover lift via shadow; this is sufficient)

**Hover state (over unpicked team):**
- Home team row: Background lightens very slightly (use Nuxt UI's `hover:bg-gray-100` light / `hover:bg-slate-800` dark) OR rely on existing card hover effect from Phase 2
- Away team row: Same treatment
- Cursor changes to pointer (standard `cursor: pointer` on clickable rows)
- Icon: a small checkmark glyph (Lucide `check`, 16px) appears to the left of the team name, with `opacity-0` transition to `opacity-100` on hover (preview what will happen when clicked)

**Picked state (active):**
- Picked team row has a **3px left border** using the team's `color` from `teams.json`
- Contrast filter applied if needed (see Color section)
- Team name text remains at Body weight/size (14px/400)
- A small **checkmark icon** (Lucide `check`, 16px, green accent color) appears to the left of team name, always visible when picked
- Unpicked team row in the same card remains neutral (no border, no checkmark)
- Clicking a picked team again clears it (PICK-02) — the checkmark disappears, border vanishes, team returns to neutral state

**Click feedback:**
- No toast/snackbar notification — the visual checkmark and border are immediate feedback that the pick is recorded (per PROJECT.md "instant" updates)
- No animation required (instant state change acceptable given the real-time standings context of Phase 5)

### Accessibility

- Entire team row is focusable: `tabindex="0"` on the team name or wrapping div
- On focus, use Nuxt UI's standard focus ring: `focus:ring-2 focus:ring-offset-2 focus:ring-green-600` (green accent)
- ARIA label on team row: `aria-label="Pick {awayTeam} over {homeTeam}"` or `aria-label="Clear pick: {pickedTeam}"`
- Keyboard support: Enter or Space on a focused team row triggers the pick toggle
- Screen reader users hear: "Pick [Team Name]" (unpicked) or "Clear pick: [Team Name]" (picked)

## Progress Indicators

### Global Progress Badge

**Placement:** Above the week-grid, aligned left, appearing just after the page title or week navigation controls. The exact placement is per Claude's Discretion (sticky navbar vs. inline above first week) — recommend inline above the first week section to avoid layout shift.

**Styling:**
- Text-based format: "{X}/{Y} picked" (per D-11)
- Font: Label role (12px/600/1.2)
- Color: Neutral text on neutral background (no accent needed; this is informational, not actionable)
- Example: "45/100 picked" in `text-slate-700` light / `text-slate-300` dark
- Optionally wrapped in a `UBadge` component with `variant="subtle"` for visual grouping, or keep as plain text

**Responsive:** Remains visible and readable on mobile (no special reflow needed)

### Per-Week Progress Badge

**Placement:** Inline with the "Week {n}" heading, immediately after the week text. Layout: `<h2>Week {n} <span class="ml-md">8/10 picked</span> <div class="buttons">Fill Week | Clear Week</div></h2>`

**Styling:**
- Text-based format: "{X}/{Y} picked"
- Font: Label role (12px/600/1.2)
- Color: Same as global badge (neutral text)
- Gap: `md` (16px) between "Week N" text and badge
- Optionally wrapped in `UBadge` with `variant="subtle"` for consistency with global badge

**Responsive:** On mobile (<640px), badges may wrap to a new line if week heading + badge + buttons exceeds available width. Preserve the badge text; wrapping is acceptable.

## Bulk Operation Buttons

### Fill Week & Fill Season Buttons

**Functionality (per PICK-05):**
- Fill Week: fills all remaining unpicked games in that week with the home team
- Fill Season: fills all remaining unpicked games in the entire season with the home team
- Existing picks are never overwritten — only unpicked games are filled

**Styling:**
- Component: Nuxt UI `UButton` with `size="sm"` and `variant="ghost"` (low-emphasis, doesn't compete with card content)
- Color: Default Nuxt UI button styling (text: neutral-700 light / neutral-300 dark, `:hover` background: subtle gray)
- Text: "Fill Week" or "Fill Season"
- Placement: Inline with week heading (after progress badge), right-aligned in the header row
- Gap: `md` (16px) before first button, `sm` (8px) between multiple buttons

**Hover state:**
- Standard `UButton` hover (slight background change)
- No icon (text-only)

**Active/Pressed state:**
- No persistent pressed state (button is momentary)
- Click performs the fill, updates the card grid, and clears the button state

### Clear Week & Clear Season Buttons

**Functionality (per PICK-06):**
- Clear Week: clears all picks in that week (no confirmation)
- Clear Season: clears all picks in the season (requires confirmation modal)

**Styling (same as Fill buttons):**
- Component: Nuxt UI `UButton` with `size="sm"` and `variant="ghost"`
- Color: Default neutral styling (same as Fill buttons)
- Text: "Clear Week" or "Clear Season"
- Placement: Inline with week heading, immediately after Fill buttons or in a separate group (both acceptable)
- Gap: `sm` (8px) between adjacent buttons

**Clear Week Click Behavior:**
- Clearing happens instantly (no confirmation per D-14)
- Picks are cleared from localStorage in a batch update (D-15)
- Card grid updates immediately to show neutral state for all cleared games

**Clear Season Click Behavior (D-14):**
- Opens a confirmation modal (UModal from Nuxt UI)
- Modal title: "Clear all season picks?"
- Modal body text: "This will clear all picks across the entire season. This action cannot be undone."
- Two buttons: "Cancel" and "Clear All" (destructive red per Nuxt UI error color)
- On "Cancel": modal closes, no change
- On "Clear All": all picks cleared, entire grid updates, modal closes

---

## Confirmation Modal (Clear Season)

**Component:** Nuxt UI `UModal` (or equivalent dialog primitive)

**Styling:**
- Title: "Clear all season picks?"
- Body: "This will clear all picks across the entire season. This action cannot be undone."
- Footer buttons:
  - "Cancel" button: `UButton` with `variant="ghost"` (secondary)
  - "Clear All" button: `UButton` with `color="red"` (destructive, using Nuxt UI's error semantic color)
- Modal width: default Nuxt UI modal width (typically 500px or auto-constrained to max 600px)
- Z-index: standard modal stacking (above all other content)

**Accessibility:**
- Modal has `role="alertdialog"` or Reka UI's built-in modal semantics (trap focus within modal, require explicit action to dismiss)
- "Clear All" button has `aria-label="Clear all season picks, this action cannot be undone"`
- Escape key closes the modal (Cancel behavior)
- Initial focus on "Cancel" button (safety default)

## Responsive Design

### Mobile (<640px)

**Game Cards:**
- Remain at full width or `minmax(280px, 1fr)` grid layout (inherited from Phase 2)
- Picked state styling (left border, checkmark) remains unchanged
- Checkmark icon size remains 16px (readable at mobile sizes)

**Week Headers & Controls:**
- Week heading ("Week {n}") remains on one line
- Progress badge ("8/10") may wrap to the next line if combined with buttons exceeds available width
- Buttons (Fill Week, Clear Week) may stack vertically on small screens or wrap to a second line
- Alternative layout on very small screens (<480px): Consider collapsing Fill/Clear buttons into a menu (⋯ icon) to save space, or remove them from the week heading and place a footer bar at the bottom of the page with global-only controls. **Left to executor discretion** if mobile UX testing shows the inline buttons are too cramped.

**Global Progress Badge:**
- Remains visible and readable
- May be moved into a fixed footer on mobile (sticky navbar), or remain inline above first week

### Tablet (640px–1024px)

- All elements remain proportional
- No special breakpoints needed; Phase 2's existing responsive card grid handles this

### Desktop (>1024px)

- All elements remain as designed; no changes

## UI Considerations

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | game card (unpicked state) | ✅ covered | Unpicked game card shows both teams with no checkmark/border; clicking either team triggers a pick. |
| partial | game card (mixed picks in one week) | ✅ covered | Week with some picks and some unpicked games renders each card in its current state (picked or unpicked); Fill Week fills only the unpicked. |
| hover | team row (unpicked) | ✅ covered | Checkmark icon fades in on hover (preview of what will appear when clicked), background subtly lightens (inherit Phase 2 card hover effect or explicit `hover:bg-gray-100`). |
| loaded | progress badges (global + per-week) | ✅ covered | Badges populated with actual count when query resolves (same timing as card grid renders). If query is still loading (initial app load), badges show "0/0 picked" or remain hidden per Phase 2's loading state pattern. |

Backstop because edge case (corruption is rare); no test coverage until Phase 4 E2E suite. |
