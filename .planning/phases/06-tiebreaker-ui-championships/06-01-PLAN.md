## Phase Goal

> **ROADMAP goal (verbatim):** Users can see exactly how each conference's championship matchup was determined, see a fully ranked 1..N conference table wherever the tiebreaker procedure can determine an order, and resolve any tie the engine can't settle on its own.

**Planner note (MVP mode):** the ROADMAP `**Goal:**` line for Phase 6 is outcome-shaped but not in the `As a … I want to … so that …` user-story form MVP mode expects. It is reproduced verbatim above rather than rewritten, per the "do not invent a story" rule. Run `/gsd mvp-phase 6` if the canonical form is wanted.

**This plan's slice.** The ACC currently falls back to plain record ordering — not its published procedure — on roughly 4% of resolutions today and, once ranks go past seed 2, on 44 of 100 fully-picked seasons. A user looking at ACC standings is being shown record order dressed as a tiebreaker result. After this plan the ACC's published procedure actually runs, and its published "the team that lost to every other Tied Team is eliminated" step is executed instead of silently dropped.

<objective>
Repair two of the three engine defects this phase must fix before any 1..N rank is displayed, and land the shared measurement harness the rest of the phase depends on.

Per D-04 this phase fixes the logged engine bugs rather than building on them. This plan takes the two that are localized to a single guard and a single step evaluator:

1. **The ACC recursion-guard trip** (`engine.ts:136-140`) — the guard encodes the wrong termination invariant and rejects the ACC's published restart behaviour.
2. **The dropped lost-to-all elimination** (`steps.ts:81`, `steps.ts:99`) — `evaluateHeadToHead` computes which team was swept by the whole tied group and then never reads the variable.

The third defect (an unseparated top bucket emitted in raw team-id order, 19.2% of contested slots) is two halves of one change with the N-seed loop and is repaired in Plan 02.

Purpose: PROJECT.md's core value is "if the standings math or the tiebreaker resolution is wrong, nothing else about the app matters." Both defects are silent-wrong, and D-01's removal of shared ranks makes both user-visible.
Output: a repaired engine, a committed reproduction test, and `tests/helpers/generated-seasons.ts` as the single generated-season harness for the whole phase.
</objective>

## Conventions resolved by this plan (binding on every later plan)

These close the open convention questions the pattern mapper and researcher flagged. They are decided here and are not to be revisited downstream.

1. **Test directory for new tiebreaker tests: nested.** Every NEW tiebreaker test in Phase 6 goes in `tests/domain/tiebreakers/`, matching Phase 5's `tests/domain/standings/` convention and 06-RESEARCH.md's file list. The nine existing flat `tests/tiebreakers-*.test.ts` files stay exactly where they are — moving them is out of scope and would churn history for no behavioural gain. `vitest.config.ts`'s `include: ['tests/**/*.test.ts']` accepts both.
2. **No barrel for `shared/domain/tiebreakers/`.** Consumers keep importing module paths directly, as `resolveTiebreakers.ts:2-3` already does. Adding an `index.ts` mid-phase would introduce a third import convention. `shared/domain/standings/index.ts` remains the one barrel.
3. **Single plain vitest project — no `defineVitestProject`** (06-RESEARCH.md Open Question 1). Every new component uses explicit `vue` imports and plain HTML controls. The page-level integration gap stays open and honestly recorded, as Phase 5 left it.
4. **Any test importing `tests/helpers/generated-seasons.ts` must carry a `@vitest-environment node` docblock**, because the helper resolves file paths through `fileURLToPath(new URL(...))` and happy-dom's global `URL` breaks it (this is the Class B failure recorded in `deferred-items.md`). `standings-tiebreaker-agreement.test.ts` already carries that docblock.
