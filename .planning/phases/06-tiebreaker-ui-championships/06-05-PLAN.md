## Phase Goal

> **ROADMAP goal (verbatim):** Users can see exactly how each conference's championship matchup was determined, see a fully ranked 1..N conference table wherever the tiebreaker procedure can determine an order, and resolve any tie the engine can't settle on its own.

**This plan's slice.** The rules that decide when the app may ask a user to break a tie by hand, and when an answer they already gave still counts. No UI yet — Plan 07 mounts it — but this is where TIE-06's whole guarantee lives, and it is testable end to end at the composable level, which is where the logic actually is.

<objective>
Build the three pure pieces of the manual-resolution lifecycle: the completion predicate, the invalidation key, and the storage composable.

TIE-06 requires a manual selection to stay valid when picks are unchanged and be invalidated rather than silently misapplied when the tied group changes. D-08 is stricter than that floor — it keys on group membership, terminal step, and every team's value at that step — and that strictness is exactly what makes D-07's conference-games-only gate safe.

06-RESEARCH.md corrected the exposure D-08 absorbs. 06-CONTEXT.md D-07 claims both the Big 12's overall-win count *and* cumulative-opponent-win-pct read outside conference games; the second half is wrong. `evaluateCumulativeOpponentWinPct` receives the conference-scoped records map and reads conference records of conference opponents, so a non-conference pick cannot move it. The real exposure is one step in one conference — the Big 12's total-wins — and the Big 12 has the lowest measured manual-decision rate of the four (0.01 per fully-picked season, 99% of seasons needing none). Implement D-07 and D-08 as decided, but do not spend disproportionate effort on that hole.

06-UI-SPEC.md §0.1 supersedes D-09: a decision is preserved and suspended when a slate goes incomplete, not discarded. That was decided by the user on 2026-08-15 with the measured ACC figure in hand (3.84 decisions per fully-picked season, p90 5, 0% of seasons needing zero), because discarding would have cost roughly four hand-made decisions covering fourteen of seventeen ACC teams every time one ACC pick was cleared.

Output: `slateCompletion.ts`, `invalidation.ts`, `useManualTiebreakers.ts`, and three test files.
</objective>

Export `ManualDecisions` as `Readonly<Record<string, readonly TeamId[]>>` — one conference's stored decisions, keyed by hash, valued by the ordered team ids the user committed. Implement a module-private `canonicalDecisionKey(group)` producing a versioned string from three components: the group's team ids sorted numerically and joined; the terminal step id, taken as the last `StepOutcome` of the last `TiebreakerCycle` in the trace; and one encoded value per sorted id, looked up from that terminal step's values.

Encode every `StepValue` variant by switching exhaustively on its `kind` discriminant and emitting the discriminant plus every field of that variant — the record variant's wins, losses and win percentage fixed to six decimal places; the head-to-head variant's result code; a literal marker for the indeterminate variant. Prefix the string with a version marker. If the trace shape or the step list ever changes, bumping the prefix invalidates every stored decision at once, which is the correct and safe behaviour rather than a migration.

Export `decisionHash(group)` returning a base-36 string, implemented as FNV-1a over the canonical key using the 32-bit offset basis and prime with `Math.imul` and an unsigned shift after each multiply.
