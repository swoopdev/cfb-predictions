## Phase Goal

> **ROADMAP goal (verbatim):** Users can see exactly how each conference's championship matchup was determined, see a fully ranked 1..N conference table wherever the tiebreaker procedure can determine an order, and resolve any tie the engine can't settle on its own.

**This plan's slice.** Everything meets. A user scanning a standings table can tell at a glance which ranks were earned on the field and which were decided by procedure, click either one to read why, and — once their conference is done — settle whatever the procedure could not.

<objective>
Integrate the three pieces built in wave 3 and wave 4 into the standings table, and close the phase's last two open items.

D-10 reverses Phase 5's D-05, which declined a tie badge on the rationale that a matching rank plus matching win-loss values were sufficient indication. Phase 5's verification measured that rationale false on about 1% of tables: ACC teams share a rank with *different* records, because the ACC ties on alternate schedule lengths rather than win percentage. The concrete defect is a table rendering one team at 6-2 above another at 7-2, both labelled rank 1. D-01 removes the shared rank that hid it and D-10 makes both cases legible.

D-11 keeps both markers in the neutral shell palette. That is not only a design preference: it reduces contrast verification from roughly 135 team pairs to two markers checked in two themes, which sidesteps the unverified per-pair item Phase 5 left open.

Also closed here: the pre-existing coverage debt on `shared/domain/tiebreakers/**`, which sits at 87.87% branches against a 90% threshold and has been failing since before Phase 5. `deferred-items.md` assigns it to whoever next works in that directory, and this phase has rewritten most of it.

Purpose: TIE-08's second half, TIE-06's user-facing wiring, and TIE-05's placement.
Output: a three-state rank cell, per-group reasoning in the table, manual decisions applied end to end, and a passing coverage gate.
</objective>
