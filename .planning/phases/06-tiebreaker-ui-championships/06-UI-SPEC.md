### 1.1 Hard constraint: no Nuxt UI components, no auto-imports, in new components

`vitest.config.ts` registers only `@vitejs/plugin-vue` — no Nuxt module, no auto-import plugin. Every new component in this phase carries state and interactive controls, so all of them are in the blast radius (`06-RESEARCH.md` Pitfall 7).

**Every new component MUST:**

- `import { computed, ref, useId } from 'vue'` explicitly — never rely on Nuxt auto-import
- use plain `<button>` / `<table>` / `<dl>` markup — never `UButton`, `UCard`, `UBadge`, `UIcon`, `UCollapsible`
- import sibling components relatively (`./TiebreakerReasoning.vue`)
- render icons as **inline `<svg>` with `stroke="currentColor"` and `aria-hidden="true"`** — the precedent is `StandingsSidebar.vue:99-111`

Nuxt UI's **semantic utility classes** (`bg-elevated`, `text-dimmed`, `ring-accented`, …) are CSS, not components, and ARE required. Use them; never a raw Tailwind palette class (`bg-slate-200`).

| sm | 8px | `gap-2`, `p-2`, `pr-2` | Table cell horizontal padding (inherited); gap between candidate names |

| xl | 24px | `py-6` | Not used in this phase (reserved) |

**Exceptions (exactly one, documented):**

- **`py-1.5` (6px)** vertical padding on standings `<tr>` cells. Inherited from `StandingsTable.vue` (Phase 5). Do **not** propagate 6px outside `<tbody>`.

No other off-scale value is permitted. `p-3 sm:p-4` on the sidebar panel is inherited and unchanged.

## 3. Typography

Three sizes, two weights. Public Sans throughout.

| Role | Size | Weight | Line height | Tailwind | Used for |
|------|------|--------|-------------|----------|----------|
| Meta / label | 12px | 600 | 1.33 | `text-xs font-semibold uppercase tracking-wide` | Championship card eyebrow; reasoning step labels; cycle headers; progress counter (weight 400 variant) |
| Body | 14px | 400 | 1.43 | `text-sm font-normal` | Table cells, step values, candidate names, ordering-interaction team names, all button labels |
| Emphasis | 14px | 600 | 1.43 | `text-sm font-semibold` | Team names inside the reasoning block; the D-17 terminus line |
| Matchup | 16px | 600 | 1.5 | `text-base font-semibold` | Resolved seed team names on the championship card — the single most important string in the phase |

**Weights: 400 and 600 only.** The inherited `font-medium` (500) on `StandingsTable`'s `<th>` column headers and rank `<td>` is grandfathered and **not** to be extended: the rank cell is rewritten in this phase and moves to 600 inside the chip (§6), and to 400 when uncontested.

**Numerals:** every rank, record, and win-percentage value uses `tabular-nums`. Inherited requirement; non-negotiable for a scannable table.

**No new size above 16px.** The championship card earns prominence through surface, position and padding (§5.1), not through display type — a 320px sidebar has no room for it.

## 4. Color

Nuxt UI semantic tokens only. Zero hex literals, zero raw palette classes, in every artefact of this phase.

| Role | Token | Usage |
|------|-------|-------|
| Dominant (60%) | `bg-default` | Sidebar panel surface; standings table background; uncontested rank cells |
| Secondary (30%) | `bg-elevated`, `bg-muted`, `bg-accented` | Championship card surface (`bg-elevated`); reasoning panel (`bg-muted`); rank chip fill and shared-rank row band (`bg-accented`); hairlines via `border-default` / `divide-default` / `ring-accented` |
| Accent (10%) | `primary` (green) | **Focus rings only** — `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-primary` |
| High-contrast neutral | `bg-inverted` / `text-inverted` / `border-inverted` | Marker (b) pill and shared-rank group rule. A token **pair** guaranteed contrasting by construction |
| Destructive | `error` | Only if P-1 resolves to option B (warn-before-destroy). Otherwise unused in this phase |

**Accent reserved for — explicit list:**

1. `focus-visible` outline on the rank-chip button
2. `focus-visible` outline on the "Show full procedure" toggle
3. `focus-visible` outline on every ordering-interaction control (team buttons, Undo last, Start over)
4. `focus-visible` outline on the card's `+N more` disclosure

**And nothing else.** This phase deliberately spends almost none of the accent budget:

- CLAUDE.md reserves visible color for **team color on picked winners**; spraying app-green across the standings panel competes with it directly.
- **D-11 forbids any color in either marker.**
- Nuxt UI's `text-primary` resolves to `green-500` in light mode (≈2.5:1 on white) and **fails WCAG AA as text**. It must not be used for any 12–14px string in this phase. This is a hard rule, not a preference.

**Colorblind safety comes free.** D-11's neutral-only mandate means both markers are already greyscale-distinguishable — they differ by *shape* and *fill weight*, not hue (§6). The visual redundancy declined at discuss-session Q5 is therefore moot here; nothing is being traded away.

**Human verification checkpoint (unavoidable, plan it as a task):** Nuxt UI injects the `--ui-color-neutral-*` ramp at runtime, so contrast cannot be statically audited (Phase 5 tried and produced a bogus 13.89:1). D-11 reduces this to **four checks total** — marker (a) chip and marker (b) pill, in light and dark. Verify at the real rendered size (12–14px), not zoomed.

## 5. Element Contract — `ChampionshipCard.vue` (TIE-07, D-12, D-13, D-14)

### 5.1 Placement and prominence

Rendered **inside `StandingsTable.vue`'s existing `<section>`, between the `<h3>` conference heading and the `<table>`.**

Rationale **[DISCRETION]**: TIE-07 says "above each conference's standings table". The `<h3>` lives inside `StandingsTable`, so composing the card from `StandingsSidebar` would place it above the heading and break the `aria-labelledby` section grouping. `StandingsTable` gains one prop (`ranking: ConferenceRanking | undefined`) and stays otherwise dumb.

Prominence is achieved without color or display type:

```
bg-elevated  ring ring-accented  rounded-lg  p-3  mb-4
```

Against the `bg-default` panel this is the only elevated surface in the sidebar — position (first thing under the heading) plus surface plus the 16px matchup type carries it.

### 5.2 Layout — vertical stack, never two columns

At 320px a side-by-side matchup with a 10-team candidate set is impossible. **Always stack**, at every breakpoint, so the shape is identical in all four conferences:

```
CHAMPIONSHIP GAME            ← 12px/600 uppercase tracking-wide, text-muted
Georgia                      ← seed 1 block
vs.                          ← 12px/400, text-dimmed, own line
One of: Duke / Miami /       ← seed 2 block
Clemson  +7 more
```

### 5.3 Seed block — the four cases

Read **`ranking.groups[0]` and `ranking.groups[1]` directly** (D-12). Never `standings[conf][0]`. Never row order. A `championshipFor(ranking)` helper returns `{ seed1, seed2 }` so the component never indexes `groups` by hand.

| Case | Seed 1 block | Seed 2 block |
|------|--------------|--------------|
| Both resolved (`groups[0].teams.length === 1 && groups[1].teams.length === 1`) | Team name, 16px/600, `text-highlighted` | Team name, 16px/600, `text-highlighted` |
| Seed 1 resolved, seed 2 pending | Team name, 16px/600 | `One of: ` + candidate set, 14px/400, `text-default` |
| Seed 1 pending (⇒ seed 2 also pending) | `One of: ` + candidate set, 14px/400 | Renders **nothing** — see below |
| Conference resolution threw | Error state, §10 | — |

**Seed 1 pending suppresses the seed 2 block.** When `groups[0]` holds *k* teams, seeds 1 **and** 2 both come out of that one group, and rendering two overlapping candidate sets would be actively misleading. The card renders a single candidate block reading `Two of: …`. **[DISCRETION]** — D-13 mandates named candidates over placeholders and this preserves that verbatim; only the connective word changes.

**D-14 compliance:** a pending seed renders **exactly one presentation** regardless of `TerminalReason` — no badge, no icon, no reason string, no "needs your decision", no distinction between `ranking-step`, `needs-scores`, `draw`, or mid-season incompleteness. The card is a statement of fact, never a call to action. `TerminalReason.ruleCitation` appears **only** inside the reasoning block (§7.4), which is TIE-05's territory and out of D-14's scope.

### 5.4 Candidate overflow — **PENDING (P-2)**

Measured group sizes at seed 2: **mean 3.7, max 10 fully picked, max 13 mid-season** (`06-RESEARCH.md` Pitfall 6). `Syracuse vs. one of: Boston College / California / Clemson / Duke / Florida State / Georgia Tech / Louisville / Miami / NC State / Wake Forest` is a paragraph, not a card.

**Provisional default — name the first 3, then `+N more`:**

- **Candidates are ordered alphabetically by school**, and a line of 12px/400 `text-dimmed` copy states `Listed alphabetically.` **This is load-bearing:** an unresolved group has *no meaningful internal order* (per Pitfall 1, `teams` order can be a raw team-id sort), so any other ordering would imply a ranking the engine never computed. Truncating an implied ranking would be a false claim of the same class as Pitfall 1.
- `+7 more` is a plain `<button>` that expands the **full list in place within the card** (a local disclosure), toggling to `Show fewer`.
- In-place rather than routing to the D-15 table expansion **[DISCRETION]**: cross-component scroll-and-expand coupling is fragile, untestable in the plain vitest project, and a routing affordance risks reading as the "act now" announcement D-17 declined. In-place is purely presentational and D-14-safe.

**Awaiting confirmation that this is presentational (inside discretion on layout) rather than an amendment to D-13.** If the user judges it an amendment, the alternative is to render all *k* names unconditionally and accept a tall card in the ACC.

## 6. Element Contract — Rank markers (D-10, D-11)

The two markers, plus the absence of a marker, form a **three-state rank cell**. Both markers are neutral-only (D-11) and differ by **shape and fill weight**, so they survive greyscale.

| State | Predicate (from engine output — never from adjacent-row W-L) | Rank cell rendering |
|-------|--------------------------------------------------------------|---------------------|
| **Uncontested** | `group.contestedWith.length === 1` | Plain number. 14px/400, `text-default`, `tabular-nums`. No chip, not interactive. |
| **Marker (a) — decided by tiebreaker** | `group.contestedWith.length > 1 && group.teams.length === 1` (`resolvedBy` is `'tiebreaker'` or `'manual'`) | `<button>` containing a **soft square chip**: `inline-flex min-w-6 justify-center rounded px-1 bg-accented text-default text-sm font-semibold tabular-nums` |
| **Marker (b) — shared rank, unresolvable** | `group.teams.length > 1` | `<button>` containing a **filled round pill**: `inline-flex min-w-6 justify-center rounded-full px-1 bg-inverted text-inverted text-sm font-semibold tabular-nums` |

**Marker (b) additionally treats the group as a unit** — the second, positional channel:

- every `<tr>` in the group gets `bg-muted`
- every `<tr>` in the group gets `border-l-2 border-inverted` — adjacent rows make it read as one continuous rule spanning the group
- the rank number still repeats on **every** row of the group. Do not render it once and blank the rest: each row must remain self-describing for a screen reader, and blanked cells were never the defect. The defect (`1 Boston College 6-2` above `1 Duke 7-2`) is fixed by the pill + band + rule making the shared rank unmistakable, not by hiding numbers.

**Derivation rules — non-negotiable:**

- Marker (a) comes from `group.contestedWith` / `group.resolvedBy`. **Never** from comparing adjacent rows' conference W-L. That is the CR-01 defect Phase 5 spent a whole plan repairing, and it gets the ACC wrong by construction (the ACC ties teams with *different* records).
- Marker (b) comes from `group.teams.length > 1`, i.e. the existing `StandingsTeam.isTied`.
- **Zero team-color classes and zero inline `style` color bindings** in either marker (D-11). A grep for `:style` and for `team.color` inside the marker markup must return nothing. Assert this in `tests/components/StandingsTable.test.ts`.

### 6.1 The chip is also the disclosure trigger

**[DISCRETION]** Any rank whose group was contested (`contestedWith.length > 1`) is expandable; uncontested ranks are not. So the chip and the pill are `<button>`s carrying `aria-expanded` and `aria-controls` pointing at the reasoning `<tr>` (§7). This unifies D-10's marker with D-15's expander: **there is exactly one affordance, and its presence means "this rank was not earned by record alone — open it to see why."**

### 6.2 Manually-ordered ranks reuse marker (a)

A group the user ordered (§8) becomes *k* single-team groups with `resolvedBy: 'manual'`. They render **marker (a)'s square chip**, identical to a procedure-decided rank.

Rationale: criterion 6 requires teams "separated only by a tiebreaker (not by record)" to be distinguishable from record-separated teams. A hand-chosen order is likewise not record-separated, so it belongs on the same side of that line. Giving it no marker would make a hand-chosen rank look record-earned — the exact failure criterion 6 exists to prevent.

**Provenance precision is delivered where TIE-05 already lives**, not by a third visual language:

- accessible name differs: `"Rank 3, decided by tiebreaker. Show reasoning."` vs `"Rank 3, decided by your choice. Show reasoning."`
- the expanded block states it in visible copy (§7.5)

**The visible payoff of completing an ordering** is that marker (b)'s pill, band and rule disappear for those teams and are replaced by *k* distinct square chips. That transition is the entire reward for the interaction — it must be immediate and must not require a reload.

## 7. Element Contract — `TiebreakerReasoning.vue` (TIE-05, D-15, D-16)

### 7.1 Position

A `<tr>` with a single `<td colspan="4">`, inserted **immediately after the last `<tr>` of the group it explains**, inside the same `<tbody>`. Not a drawer, not a modal, not a popover (D-15). Rendered only when expanded; the `<tr>` is absent from the DOM when collapsed.

Panel inside the cell: `bg-muted rounded-md p-3 my-1 text-left`.

### 7.2 Default depth — decisive step first (D-16)

The decisive step is `trace.at(-1).steps` filtered to the last entry with `separated === true`.

```
DECIDED AT · HEAD-TO-HEAD          12px/600 uppercase tracking-wide, text-muted
Duke            beat all others    <dl>: <dt> 14px/600 text-highlighted
Miami           mixed                    <dd> 14px/400 text-default
Clemson         lost to all others
NC State        lost to all others
Show full procedure                14px/400 text-toned underline, plain <button>
```

Values render as a `<dl>` laid out `grid grid-cols-[minmax(0,1fr)_auto] gap-x-2 gap-y-1`. A `<dl>` rather than a nested `<table>`: nested tables inside a `<td>` are hostile to screen readers and to a 320px column.

`StepValue` rendering — one string per variant, no icons:

| `kind` | Rendered |
|--------|----------|
| `record` | `4-1 (.800)` — `tabular-nums` |
| `headToHead` | `beat all others` / `lost to all others` / `mixed` / `no shared games` |
| `indeterminate` | `not applicable` — `text-dimmed` |

### 7.3 Full procedure (toggle) — TIE-05 completeness

Toggling `Show full procedure` reveals every cycle in order, above the decisive-step block, and relabels the button `Hide full procedure`.

```
CYCLE 1 · TIED: DUKE, MIAMI, CLEMSON, NC STATE, LOUISVILLE
  Head-to-head           no separation
  Common opponents       Duke 3-1 · Miami 3-1 · Clemson 2-2 · NC State 2-2 · Louisville 1-3
  → Restarted. Duke, Miami seeded at common opponents.
CYCLE 2 · TIED: CLEMSON, NC STATE, LOUISVILLE
  Head-to-head           Louisville eliminated
  ...
```

- Cycle header: 12px/600 uppercase, `text-muted`, from `TiebreakerCycle.tiedTeams`
- Step rows: step name 14px/400 `text-default`; per-team values as the same `<dl>` grid
- **Restart events** (`outcome === 'restart'`): their own line, prefixed `→ `, 14px/400, `text-toned`, naming `removed[].teamId`, `removed[].reason` (`seeded` / `eliminated`) and `removed[].atStep`. Restarts are **required content** (TIE-05) and must never be collapsed away.
- Non-separating steps read `no separation` in `text-dimmed`

**Trace isolation is a display correctness requirement, not just an engine one.** Each group's `trace` must contain only teams drawn from that group's `contestedWith` (Pitfall 5). If the reasoning block renders a head-to-head between two teams not in the group, the engine is aliasing one `cycles` array across iterations. Assert it.

### 7.4 Terminal reason

For an **unresolved** group only, the block ends with the engine's `TerminalReason`:

```
No further step applies.                              14px/400 text-default
"{reason.ruleCitation}"                               12px/400 text-muted, italic
— {reason.sourceName}                                 12px/400 text-dimmed
```

This is TIE-04/TIE-05's required "explanation of why" and is explicitly **not** a D-14 violation: D-14 scopes the *card*, not the reasoning surface.

### 7.5 Manual provenance

For a group with `resolvedBy: 'manual'`, the block leads with:

```
DECIDED BY YOU
You ranked these teams in this order. It applies while
this conference's slate is complete and its picks are unchanged.
```

followed by the ordering the user chose, then the full-procedure toggle showing what the engine exhausted first. This is the visible statement of D-08/D-09's ephemerality, placed where the user will actually meet it.

## 8. Element Contract — Group ordering interaction (TIE-06, D-17, model B)

The only genuinely interactive new control in the phase. Lives **inside the same expanded reasoning block, as its terminus** (D-17) — no modal, no separate call-out chrome, no announcement anywhere else.

### 8.1 Gate

Rendered **only** when both are true:

1. `group.teams.length > 1` (unresolved), and
2. `slateComplete[conference] === true` (D-07 predicate: every game where both teams are in that conference is picked)

Mid-season, an unresolved group's expansion ends at §7.4 with no prompt. **This is correct and must not read as broken** — see §11.

### 8.2 Interaction — sequential assignment, not drag, not up/down

The user assigns positions by clicking teams in finishing order. *k* clicks orders *k* teams.

Rejected: drag-and-drop (needs a dependency, hostile at 320px, unusable by keyboard, untestable in happy-dom); per-row ▲/▼ (O(k²) clicks — unusable at the measured max of 10); a `<select>` per team (k×k options, conflict resolution nightmare).

```
Nothing separates these — you choose.        14px/600 text-highlighted
Click each team in the order they finish.    12px/400 text-muted

  (1)  Duke                                  assigned — pill + name, not a button
  (2)  Miami
       Boston College                        unassigned — plain <button>, full width
       California
       Clemson
       …

Ranked 2 of 10.        Undo last   Start over
```

- **Assigned rows** move to the top of the list, in assigned order, prefixed by marker (b)'s round pill carrying their position. They are static text, not buttons. Correction is via `Undo last` / `Start over` only — this keeps the control small, unambiguous, and testable.
- **Unassigned rows** are `<button type="button">`, full width, `text-left text-sm px-2 py-1.5 rounded bg-elevated hover:bg-accented transition-colors` plus the standard `focus-visible` accent ring. Order them **alphabetically by school** — same reasoning as §5.4: the group has no meaningful internal order.
- **Progress line** `Ranked 2 of 10.` — 12px/400 `text-muted`.
- `Undo last` / `Start over` — 14px/400 plain `<button>`s, `text-toned underline`. `Undo last` is `disabled` at zero assigned; `Start over` is `disabled` at zero assigned.

### 8.3 Commit semantics

The ordering is **local component state until every team is assigned**, then it writes to storage in one operation. Partial orderings are never persisted.

Rationale: model B is "order the entire group in one interaction". A persisted partial ordering would be exactly the suspended-limbo third state D-09 was chosen to eliminate.

On commit the group collapses into *k* single-team groups with `resolvedBy: 'manual'`, the table re-renders with *k* distinct square chips, and the reasoning block re-renders per §7.5.

### 8.4 Usable at *k* = 10 — the sizing check

At the measured worst case (10 fully picked, 13 mid-season) the control is a vertical list of 13 rows at 6px+14px+6px ≈ 26px each ≈ **340px tall** inside a sidebar that is already `lg:max-h-[calc(100vh-6rem)] overflow-y-auto`. That is acceptable: it is inside an already-scrolling panel and only ever one group at a time is expanded per conference.

**No max-height, no inner scroll region on the list.** A nested scroll container inside an already-scrolling sidebar is the worse failure. If a viewport genuinely cannot show it, the outer sidebar scroll is the correct mechanism.

## 9. D-09 lifecycle presentation — **PENDING (P-1)**

### 9.1 The precise mechanism

Two distinct invalidation paths exist. **D-08 is settled and is not in question here.**

| Mechanism | Trigger | Scope | Status |
|-----------|---------|-------|--------|
| **D-08** hash | Group membership, terminal step, or any team's value at that step drifts | Per decision | **Settled.** Recompute on read; a stale entry simply never matches |
| **D-09** discard | The conference slate stops being complete | **All** decisions for that conference | **PENDING (P-1)** |

**Sharpened:** flipping a pick's winner does *not* trip D-09 — the game is still picked, so the slate is still complete. Only **clearing** a conference pick does. The realistic ways a user clears one are `Clear Week` and `Clear Season` (`app/pages/week/[week].vue:136-144`) — bulk operations that today fire with no confirmation and no awareness that tiebreaker decisions exist.

### 9.2 The measured blast radius

- **ACC, fully picked:** ~3.84 orderings (p90 = 5) covering ~14 of 17 teams. **0% of seasons need zero.**
- Clearing one ACC conference pick — or running `Clear Week` on any week containing an ACC conference game — discards **all of them**.
- The table silently reverts from 17 distinct ranks to **6.5 distinct ranks across 17 teams (85% sharing a rank)**.
- D-17 provides **no announcement**, so nothing tells the user this happened or why.
- SEC 0.10 / Big Ten 0.19 / Big 12 0.01 — in the other three conferences this costs essentially nothing, in 83–99% of seasons.

### 9.3 The three options

| | Behaviour | Cost | Keeps D-09's stated guarantee? |
|---|---|---|---|
| **A — Silent discard** *(D-09 as decided)* | Slate goes incomplete → conference's decisions deleted from storage. No notice. | ~4 ACC orderings destroyed with zero feedback; the ACC table visibly degrades with no explanation. UAT signal: *"my ACC standings keep resetting."* | Yes |
| **B — Warn before destroying** | Clearing a pick that would make a complete slate incomplete, for a conference holding decisions, prompts first. Confirm → discard (identical to A). Cancel → pick unchanged. | Adds a confirm dialog to the app's single most-used interaction. In practice fires only on ACC picks. `Clear Week` / `Clear Season` must aggregate across conferences into one prompt. Costs a destructive-confirm UI (~1 new component). | Yes |
| **C — Preserve and suspend** | Decisions stay in storage but are **not applied** while the slate is incomplete. On re-completion they re-apply only where the D-08 hash still matches; non-matching entries are dropped. | Adds a third *storage* state. **But not a third UI state** — a suspended decision renders exactly as a discarded one (nothing), so the display is still two-valued. D-08's hash already provides the re-application mechanism at no extra cost. Needs a storage cap (Pitfall 8). | **Yes — identically.** Nothing hand-chosen is ever *displayed* under unapproved conditions; only storage retention differs |

**Recommendation: C.** D-09's rationale was "a hand-chosen rank is never displayed under conditions the user did not approve." C satisfies that literally and exactly — a suspended decision is not applied, so it is not displayed. The rejected "third state" is confined to storage, where the user never sees it, while the destructive consequence D-09 accepted on a ~1-decision assumption is eliminated at the 3.84-decision reality. B is the fallback if the two-state storage machine is judged worth protecting; A is only defensible if the ACC number is expected to drop sharply after the fourth engine repair (the missing "lost to all others" elimination), which is **currently unmeasured**.

**Provisional default recorded for planning:** C. **Not consent.**

### 9.4 If B is chosen — destructive-confirm contract

Only this option adds UI. Copy:

> **Clear 4 tiebreaker decisions?**
> Clearing this pick makes the ACC slate incomplete, which clears the 4 tiebreaker orderings you set for it. You'll be asked again once the slate is complete.
> `[Clear pick and decisions]` (`error`) · `[Keep pick]` (neutral, default focus)

Counts are live, never hard-coded. For `Clear Week` / `Clear Season`, one prompt aggregating all affected conferences — never one prompt per conference.

**Do not hard-code "~4"** anywhere in copy or layout (`06-RESEARCH.md` planning implication 2): a pending engine repair may lower it.

| Element | Loading | Empty | Error |
|---------|---------|-------|-------|
| **ChampionshipCard** | Renders **nothing**. | **Rank markers** | n/a (table not rendered) | n/a | Degraded path: **no chips, no pills, no bands** — every team is its own rank group ordered by record. Nothing may be marked tiebreaker-decided when no tiebreaker ran |
| **TiebreakerReasoning** | n/a | n/a — uncontested ranks have no trigger, so no empty state can be reached | Not rendered on the degraded path |

**Championship card empty state, rationale [DISCRETION]:** at zero picks every team is 0-0 and the engine produces one whole-conference group, so the card would render `Two of: <16 alphabetical names> +13 more` on first load — a nonsense first impression. The empty state fires **only at literally zero picked conference games**, which is an absence-of-data condition, not a pending-tie condition, and so does not reintroduce the pending-reason distinction D-14 declined. Flagged here explicitly so the checker or the user can veto it.

**Championship card error state:**

> **Tiebreakers unavailable**
> We couldn't resolve this conference's procedure. The standings below are ordered by record only. Changing a pick may resolve it.

12px/600 uppercase heading, 14px/400 body, `text-muted`. No `error` color — this is a degraded state, not a user error, and coloring it red in a sidebar that also degrades quietly would overstate it. Never render the raw exception. Logging stays subject to T-05-03-03: **conference name and error object only — never picks, storage keys, or share codes.**

## 11. Mid-season shared ranks must read as intentional

Prompting is gated on slate completion (D-07), and ties resolve *less* early in a season. Mid-season the ACC legitimately shows **4.1 distinct ranks across 17 teams (96% sharing a rank)**. This is correct output, not an unfinished state.

Required behaviour:

- **No nagging.** No badge, no count, no "N ties unresolved", no dot, no pulsing affordance, anywhere — in the card, the table, the sidebar, or the page.
- **Marker (b) is a statement, not a warning.** `bg-inverted` neutral pill and `bg-muted` band — no `error`/`warning` color, no alert icon, no `role="alert"`.
- **The reasoning block is always available**, mid-season included. It ends at §7.4's terminal reason with no prompt — which reads as "here is why these are level right now," not "you owe us something."
- **Nothing in the phase says "incomplete", "unfinished", "missing", or "needs".** The word to reach for is **tied**.
- The table's convergence toward clean 1..N as picks fill in is the feedback. No progress meter for it.

## 12. Keyboard & Screen Reader Contract

The ordering interaction is the only new control that needs more than default semantics; everything else is native elements used natively.

### 12.1 Rank chip / pill (the disclosure trigger)

| Property | Value |
|----------|-------|
| Element | `<button type="button">` inside the rank `<td>` |
| `aria-expanded` | bound to the group's expansion state |
| `aria-controls` | `useId()` of the reasoning `<tr>`'s panel |
| Accessible name | `Rank 3, decided by tiebreaker. Show reasoning.` / `Rank 3, decided by your choice. Show reasoning.` / `Rank 3, tied with 3 other teams. Show reasoning.` |
| Focus | `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-primary` |
| Uncontested ranks | **Not a button.** No tab stop, no ARIA. A non-interactive number |

Marker semantics reach assistive tech through the **accessible name**, not through the visual treatment — a band and a pill convey nothing to a screen reader. The user declined *visual* colorblind redundancy at Q5; that decision does not extend to accessible names, and TIE-05's premise is that the reasoning is available.

### 12.2 "Show full procedure" toggle

`<button type="button">` with `aria-expanded` + `aria-controls`. Label text flips between `Show full procedure` and `Hide full procedure` — never an icon-only control.

### 12.3 Ordering interaction

| Concern | Contract |
|---------|----------|
| Grouping | Wrapper `<div role="group" :aria-labelledby="terminusId">` where `terminusId` is the "Nothing separates these — you choose." line |
| Team buttons | `<button type="button">`, natural tab order, Enter/Space activate. No custom key handling, no roving tabindex, no arrow-key navigation — a plain button list needs none |
| Accessible name | `aria-label="Rank {School} 3rd"` where the ordinal is the next open position, recomputed on every assignment |
| **Focus after assignment** | **Move focus to the first remaining unassigned team button.** The activated button leaves the unassigned list, so focus would otherwise be lost to `<body>` and keyboard users would be stranded. This is the single most important a11y detail in the phase |
| Focus on completion | Move focus to `Start over` |
| Focus on `Undo last` | Stays on `Undo last` while it remains enabled; moves to the first unassigned team button when it becomes disabled |
| Live region | The progress line carries `role="status"` (implicit `aria-live="polite"`). Content: `Duke ranked 1. 9 teams remaining.` after each assignment; `All 10 teams ranked.` on completion. Never `aria-live="assertive"` |
| Assigned rows | Static text, not focusable. Position pill has `sr-only` text `Position 1` |
| Touch targets | Team buttons are full-width at 26px tall — below the 44px guideline, and accepted: they sit inside a dense standings table where a 44px row would break the table's rhythm entirely. Full-row width is the compensating affordance. **This is the one accessibility trade in the phase; record it in UAT** |

### 12.4 Reasoning panel

- `<dl>` for team→value pairs; `<dt>` is the team, `<dd>` is the value
- The panel `<td colspan="4">` carries the `id` referenced by `aria-controls`
- Collapsed groups have **no reasoning `<tr>` in the DOM at all** — not `hidden`, not `display:none`. Keeps the table's row count honest for screen readers

**Tone rules for this phase:**

- Sentence case for all body copy; UPPERCASE only for the 12px eyebrow/label role
- No exclamation marks. No "Oops". No "Sorry"
- **Never** the words `incomplete`, `unfinished`, `missing`, `pending`, or `needs` in user-visible standings copy — say **tied**. (`incomplete` appears once, in the P-1 = B destructive confirmation, where it is literally accurate and the user is mid-action)
- Never state or imply a count of outstanding decisions anywhere outside an expanded group (D-17 declined the call-out)
- **Never hard-code "~4"**, "a few", or "one last tie" — the number is measured, conference-dependent, and a pending engine repair may move it
- Team names always render as `school` — never abbreviation, never mascot
