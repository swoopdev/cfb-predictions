## Phase Goal

> **ROADMAP goal (verbatim):** Users can maintain multiple independent what-if scenarios side by side, with no account required.

**Planner note (MVP mode):** see Plan 07-01's Phase Goal section for the full discrepancy note on this ROADMAP line's format (outcome-shaped, not literal "As a … so that …" form) and the synthesized user-story equivalent offered there. Not repeated verbatim here to avoid drift between plans; that plan's note is authoritative.

**This plan's slice.** Still no new UI. After this plan, the progress badges and the standings/tiebreaker derivation pipeline — the two things a user actually looks at every time they make a pick — are scenario-aware end to end, so Plan 07-05's page-level wiring has nothing left to invent; it only has to pass the right id down.

<objective>
Thread the `scenarioId` parameter Plan 07-01 established through the two derived composables that consume `usePicksStorage`/`useManualTiebreakers` internally (`usePickProgress`, `useStandings`), and through the two display components that call `usePicksStorage`/`usePickProgress` directly (`PickProgress.vue`, `PickProgressWeek.vue`).

Purpose: these four files are the layer between raw storage and the rendered page. If any one of them keeps calling a composable with only a `season` argument, TypeScript will not compile once Plan 07-01 lands (scenarioId has no default) — this plan is that required, mechanical propagation, plus the accompanying test call-site updates RESEARCH.md's Pitfall 4 flagged (52 call sites across 4 test files).
Output: `usePickProgress`, `useStandings`, `PickProgress.vue`, `PickProgressWeek.vue` all require a scenario id and pass it through unchanged; full test suite compiles and passes again.
</objective>

## Conventions inherited from Plan 07-01 (binding, do not revisit)

1. Every scenario-scoped storage key is built exclusively via `app/utils/scenarioKeys.ts` — never a hand-typed template literal.
2. Signature order is `(scenarioId: string, season = 2026)` on every scenario-scoped composable — required parameter first, defaulted parameter second (Pitfall 2).
3. `usePicksStorage`, `useAutoFilledGames`, `useManualTiebreakers` now take `(scenarioId, season)` — this plan calls them with both arguments, never the old single-argument form.
4. Test fixture convention: `const SCENARIO_ID = 'scenario-1'` alongside the existing `const SEASON = 2026`.
