Before constructing any `useStorage()` call, read `const hadNoRegistryBefore = localStorage.getItem(scenarioKeys.registry(season)) === null`. This MUST happen first: VueUse's `useStorage` defaults to `writeDefaults: true`, meaning the very first `useStorage()` call synchronously persists its default value to localStorage — checking for a null registry key AFTER constructing the ref would always read false (Pitfall 5's writeDefaults corollary).

Construct `const registry = useStorage<ScenarioMeta[]>(scenarioKeys.registry(season), [], localStorage, { serializer: { read, write } })`. `read(v)` `JSON.parse`s `v`; on any thrown error, returns `[]` (D-17 — silent reset, no `_corrupt` key, no console output, mirroring `useManualTiebreakers.ts`'s disposition, not `usePicksStorage.ts`'s). On successful parse, calls a module-level `validateRegistry(parsed): ScenarioMeta[]` helper: if `parsed` is not an array, return `[]`; otherwise iterate entries, keep only those where `id`/`name`/`createdAt` are all non-empty strings (mirror `useManualTiebreakers.ts`'s `isValidOrderedIds`-style type guard, written as `isValidScenarioMeta`), and de-duplicate by `id` keeping the first occurrence (Security Domain V5, Known Threat Pattern 3 — a hand-edited registry with a repeated id must not let one scenario's write silently clobber another's). `write(v)` is `JSON.stringify(v)`.

Construct `const activeScenarioId = useStorage<string>(scenarioKeys.active(season), '', localStorage)` — a plain string value; VueUse's default JSON serializer is sufficient here (RESEARCH.md's Anti-Patterns note: primitive storage carries none of Pitfall 1's shared-object-reference risk, since a fresh string primitive is created on every read regardless of default reuse).

Add a synchronous recovery pass, run unconditionally after both refs are constructed and BEFORE `useScenarios` returns (Pitfall 5 — this must never be a `watch`/`onMounted` deferred effect): if `registry.value.length === 0`, assign `registry.value = [{ id: crypto.randomUUID(), name: 'Scenario 1', createdAt: new Date().toISOString() }]` (a minimal inline default for this task; Task 2 replaces this literal with a call to the real `createScenario()` once it exists, so the naming rule is defined in exactly one place).
