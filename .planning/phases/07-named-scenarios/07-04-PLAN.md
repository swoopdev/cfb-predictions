## Phase Goal

> **ROADMAP goal (verbatim):** Users can maintain multiple independent what-if scenarios side by side, with no account required.

**Planner note (MVP mode):** see Plan 07-01's Phase Goal section for the full discrepancy note on this ROADMAP line's format and the synthesized user-story equivalent; not repeated here.

**This plan's slice.** After this plan, a user can visually see and interact with every CRUD affordance SCEN-02/03/04 require — select a scenario, rename it inline, duplicate it, request its deletion, add a new one — as real, tested Vue components. They are not yet mounted in the running app (Plan 07-05); this plan proves each component's own event contract is correct in isolation, the same discipline `PickProgress.vue`'s own test suite already applies to its composable-facing half.

<objective>
Build `ScenarioSwitcher.vue` (a `USelectMenu`-based switcher with inline per-row rename/duplicate/delete affordances and a pinned "+ New Scenario" row) and `DeleteScenarioModal.vue` (a `UModal`-based delete confirmation), both first-time uses of these two Nuxt UI 4 components in this codebase.

Purpose: 07-CONTEXT.md's D-08 and D-12 lock these two specific Nuxt UI components as the switcher and confirmation mechanism; 07-UI-SPEC.md fixes their exact copy, icon set, and color allocation. Nothing here needs a design decision — it needs a faithful, tested implementation of decisions already made.
Output: two new components with full test coverage of their own event contracts, ready for Plan 07-05 to wire to real composable state.
</objective>
