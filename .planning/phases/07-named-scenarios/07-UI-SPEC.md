## Spacing Scale

Declared values (must be multiples of 4) — this is the scale already in use throughout `app/pages/week/[week].vue`, `GameCard.vue`, `ChampionshipCard.vue`; Phase 7 introduces no new values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside switcher rows (`gap-1`) |
| sm | 8px | Compact spacing between header controls (`gap-2`), row-internal icon button spacing |
| md | 16px | Default spacing between header control groups (`gap-4`), modal body padding |
| lg | 24px | Section padding, spacing between header control rows (`gap-6`) |
| xl | 32px | Vertical rhythm between major page sections (`space-y-8`) |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions: icon-only touch targets (rename/duplicate/delete row buttons) get a 32px (`size-8`) minimum hit area even though the icon itself renders at 16px (`size-4`), matching `GameCard.vue`'s existing checkmark-icon touch-area pattern (`w-4 h-4` icon inside a `w-4 h-4` positioned slot with surrounding `px-2 py-2` clickable row). Delete icon button specifically should be `size-8` minimum per general touch-target guidance, since it triggers a destructive modal.

## Typography

Reuses the exact size/weight pairs already established across the codebase (`GameCard.vue`, `week/[week].vue`, `ChampionshipCard.vue`) — no new sizes or weights introduced this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`, uppercase, `tracking-wide`) | 600 (`font-semibold`) | 1.2 |
| Heading | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 |
| Display | 24px (`text-2xl`) | 600 (`font-semibold`) | 1.2 |

Applied this phase:
- **Switcher trigger button label** (active scenario name): Body (14px/400)
- **"+ New Scenario" row label**: Body (14px/400), paired with `lucide:plus` icon
- **Delete confirmation modal title** ("Delete {scenario name}?"): Heading (20px/600)
- **Delete confirmation modal body copy**: Body (14px/400)
- **Inline rename text input**: Body (14px/400) — matches the row label it replaces, no size jump on edit
- Exactly 2 weights total (400, 600) — matches the codebase-wide constraint already in effect; no new weight is introduced.

## Color

Reuses Nuxt UI's existing semantic token ramp (`primary: green`, `neutral: slate`) rather than introducing new hex values. The 60/30/10 split below documents how those tokens are already allocated across the app and how Phase 7's new surfaces (switcher dropdown, delete modal) slot into the same allocation.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Nuxt UI `bg-default` (slate ramp, light/dark aware) | Page background, modal backdrop area, switcher dropdown panel background |
| Secondary (30%) | Nuxt UI `bg-elevated` / `bg-muted` (slate ramp) | Switcher trigger button surface, dropdown row hover state, modal panel surface, `ChampionshipCard`-style bordered panels |
| Accent (10%) | Nuxt UI `primary` = green (`--color-green-400` `#00DC82` family) | Reserved for: the active-scenario indicator/checkmark inside the switcher dropdown row, the "+ New Scenario" row's icon/label, the delete confirmation modal's non-destructive action emphasis (if any), and reuse of the existing `bg-primary` progress-bar fill pattern — nowhere else |
| Destructive | Nuxt UI `error` semantic color (red ramp) | Reserved for: the per-row delete icon button, and the delete-confirmation `UModal`'s confirm button (`color="error"`) — never for rename/duplicate, which stay neutral |

Accent reserved for: active-scenario checkmark/indicator in the `USelectMenu` dropdown, "+ New Scenario" row affordance, and the switcher trigger's active state only. Rename and duplicate icon buttons stay neutral (`color="neutral"`, `variant="ghost"`) — they are not the primary action of the row and must not compete visually with the accent-reserved create/active-indicator elements.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `+ New Scenario` — pinned row inside the switcher `USelectMenu` (D-10); creates a scenario named `Scenario {N}` (N = current count + 1, D-11), immediately editable inline |
| Switcher trigger label | `{active scenario name}` with a `lucide:layers` leading icon — e.g. button reads "Scenario: My Scenario" or simply the name itself if space-constrained; exact truncation behavior at Claude's discretion during implementation, but the full name must be recoverable via `title` attribute or tooltip |
| Rename affordance | No standalone label — `lucide:pencil` icon button per row, `aria-label="Rename {scenario name}"`; click swaps the row's static label for an inline text input pre-filled with the current name, saved on blur/Enter |
| Duplicate affordance | No standalone label — `lucide:copy` icon button per row, `aria-label="Duplicate {scenario name}"`; produces a new scenario named `{Original Name} (copy)`, immediately editable inline exactly like a newly-created scenario |
| Delete affordance | No standalone label — `lucide:trash-2` icon button per row, `aria-label="Delete {scenario name}"`; disabled (not hidden) when exactly one scenario remains (D-14), with `title="At least one scenario is required"` on the disabled state so the reason is discoverable |
| Empty state | **Not applicable this phase.** D-14 guarantees the registry always holds at least one scenario (auto-created if the registry is ever empty, per D-05/D-17) — there is no zero-scenario UI state to design for |
| Error state | **Not applicable this phase.** D-17 mandates silent recovery from a corrupted scenario registry (reset to a fresh default scenario) with no error banner shown to the user — this is a deliberate continuation of the `usePicksStorage` D-07/D-08 precedent, not an oversight |
| Destructive confirmation | **Delete scenario:** Modal title `Delete "{scenario name}"?` — Body: `This permanently removes its picks, auto-fill history, and tiebreaker decisions. This can't be undone.` — Confirm button: `Delete scenario` (`color="error"`) — Cancel button: `Cancel` (`color="neutral"`, `variant="ghost"`) |
