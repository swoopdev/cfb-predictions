## Spacing Scale

Declared values (must be multiples of 4) — same scale already in use throughout the codebase; this phase introduces no new values:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps (`gap-1`) |
| sm | 8px | Compact spacing between header controls (`gap-2`), row-internal icon button spacing, spacing between the share-URL input and its Copy Link button |
| md | 16px | Modal body padding, banner internal padding, spacing between banner icon/text/action (`gap-4`) |
| lg | 24px | Section padding, spacing between the banner and the content below it (`mb-6`-equivalent, matching the switcher's existing `mb-6`) |
| xl | 32px | Vertical rhythm between major page sections |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions: the Share icon button (new, `ScenarioSwitcher.vue` row) gets the same `size-8` (32px) minimum hit area as the existing rename/duplicate/delete row buttons — no new exception, just extending the established one to a fourth icon. `UAlert`'s built-in dismiss (×) button and action-slot buttons already meet the 32px minimum via Nuxt UI's default sizing — no override needed.

## Typography

Reuses the exact size/weight pairs already established codebase-wide — no new sizes or weights introduced this phase:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 |
| Label | 12px (`text-xs`, uppercase, `tracking-wide`) | 600 (`font-semibold`) | 1.2 |
| Heading | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 |
| Display | 24px (`text-2xl`) | 600 (`font-semibold`) | 1.2 |

Applied this phase:
- **Share modal title** (`Share "{scenario name}"`): Heading (20px/600) — matches `DeleteScenarioModal.vue`'s title exactly
- **Share modal body copy**: Body (14px/400)
- **Share-URL input field text**: Body (14px/400), truncated with ellipsis when the field is narrower than the encoded string; full value selectable via focus (`select-all` on focus, this phase's Clipboard-fallback mechanism)
- **Copy Link button label**: Body (14px/400) inside a `UButton`, standard Nuxt UI button typography — no size override
- **Banner title** (e.g. "You're viewing a shared scenario"): Body size at semibold weight (14px/600) — composed from the existing size/weight pairs, not a new role; matches `UAlert`'s own title-slot convention of bolding the size already in use for body text at this density
- **Banner description body**: Body (14px/400)
- Exactly 2 weights total (400, 600) — unchanged, no new weight introduced

## Color

Reuses Nuxt UI's existing semantic token ramp (`primary: green`, `neutral: slate`) plus two **new** Nuxt UI default semantic tokens this phase needs for banner states — `info` (default blue ramp, unconfigured in `app.config.ts`) and `warning` (default amber ramp, unconfigured) — because D-08 requires the shared-scenario banner to visibly distinguish its normal state from its schedule-mismatch state, and Nuxt UI's built-in semantic colors are the correct existing mechanism for that rather than inventing new hex values.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Nuxt UI `bg-default` (slate ramp) | Page background, modal backdrop area — unchanged |
| Secondary (30%) | Nuxt UI `bg-elevated` / `bg-muted` (slate ramp) | Modal panel surface, share-URL input surface, switcher trigger/row surfaces — unchanged |
| Accent (10%) | Nuxt UI `primary` = green (`--color-green-400` `#00DC82` family) | Reserved for: the active-scenario checkmark in the switcher dropdown, the "+ New Scenario" row affordance, the switcher trigger's active state, and **(new this phase)** the Share modal's **Copy Link** button (`color="primary"`, `variant="solid"`) — the single meaningful action in that read-only modal, same "one accent action per surface" rule Phase 7 established for "+ New Scenario" |
| Info (new) | Nuxt UI `info` semantic (default blue ramp) | Reserved for: the shared-scenario banner's default/matched-schedule state only (D-05) — icon, border/left-accent, and "Save a copy" action button all inherit this one color |
| Warning (new) | Nuxt UI `warning` semantic (default amber ramp) | Reserved for: the same banner's schedule-mismatch variant only (D-08, "N of M picks applied") — same slot, swapped color, never combined with the info variant on screen at once |
| Destructive / Error | Nuxt UI `error` semantic (red ramp) | Reserved for: the existing per-row delete icon button and delete-confirmation modal (Phase 7, unchanged) **plus (new this phase)** the malformed/unreadable-payload banner (D-11, "This link couldn't be read") — same token family, a legitimate second usage since Nuxt UI's `error` semantic already covers both destructive actions and error states elsewhere in the ecosystem; never used for anything else |

Accent reserved for: active-scenario checkmark/indicator, "+ New Scenario" row affordance, switcher trigger active state, and the Share modal's Copy Link button — nowhere else. The new per-row **Share** icon button stays **neutral** (`color="neutral"`, `variant="ghost"`), matching rename/duplicate — it is not the primary action of the row and must not compete with the accent-reserved elements above.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **Share** — icon-only per-row action in `ScenarioSwitcher.vue` (`lucide:share-2`, `color="neutral"`, `variant="ghost"`, `class="size-8"`, `aria-label="Share {scenario name}"`), positioned alongside rename/duplicate/delete (D-01); opens the Share modal |
| Share modal title | `Share "{scenario name}"` (declarative, not a question — this action has no consequence to confirm, unlike Delete) |
| Share modal body | `Anyone with this link can view these picks.` above a read-only URL field |
| Share modal action | **Copy Link** (`lucide:copy`, `color="primary"`, `variant="solid"`) — on successful copy, swaps to **Copied!** (`lucide:check`) for ~2 seconds then reverts, mirroring `GameCard.vue`'s existing checkmark-swap precedent |
| Copy fallback (Claude's discretion per D-13) | If the Clipboard API is unavailable, the field auto-selects its full text on focus so a manual Ctrl/Cmd+C works — the selection behavior itself is the fallback; no separate error copy is needed |
| Shared-scenario banner — default state (D-05) | Title: `You're viewing a shared scenario` — Body: `These picks aren't saved to your device yet.` — Action: **Save a copy** (`color="info"`) — Dismiss: `UAlert`'s built-in close (×) |
| Shared-scenario banner — mismatch state (D-08) | Title: `{N} of {M} picks applied` — Body: `This link was created for a different schedule version.` — Action: **Save a copy** (`color="warning"`, still offered — this is a partial-application warning, not a hard failure) — Dismiss: × |
| Malformed/unreadable payload banner (D-11) | Title: `This link couldn't be read` — Body: `The share link is invalid or corrupted. Your own picks are unaffected.` — **No "Save a copy" action** (nothing valid decoded to save) — Dismiss: × only |
| Oversized payload (D-10) | Same banner and copy as "This link couldn't be read" above — the visitor has no actionable reason to distinguish "too large" from "corrupt"; both are the cheap-reject path |
| Empty state | Not applicable — sharing works at any pick state including zero picks (D-03, mirroring Phase 4 D-11's "picks can change at any time"); there is no zero-picks-blocks-sharing state to design for |
| Error state | Covered entirely by the malformed/unreadable and mismatch banners above — no separate generic error state exists this phase |
| Destructive confirmation | Not applicable — this phase adds no new destructive action. The existing Delete Scenario confirmation (Phase 7, `DeleteScenarioModal.vue`) is unchanged and is not touched by Share |
