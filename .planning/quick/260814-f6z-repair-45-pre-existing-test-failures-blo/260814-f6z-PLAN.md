45 = 2 + 22 + 21. The seven Class A/B files contribute 0 to that count because

**Class A — alias misuse (verified error text: `Failed to resolve import`).**
`vitest.config.ts` maps `~` -> `./app` and `#shared` -> `./shared`. So a
specifier that puts `shared/` or `app/` *after* the tilde resolves to
`app/shared/...` or `app/app/...`, neither of which exists.

**Class B — global happy-dom (verified error text: `TypeError: The URL must be
of scheme file`).** Commit `acf2de6` (Phase 04-01) added
`environment: 'happy-dom'` globally. These four files call
`fileURLToPath(new URL(..., import.meta.url))` to read source files off disk;
under happy-dom the global `URL` is happy-dom's, so the constructed URL is not
`file:`-schemed and Node's `fileURLToPath` rejects it. Proven: running these
four with `--environment node` passes 42/42.

**Class C — `ofetch` (verified error text: `Failed to resolve import "ofetch"
from "app/utils/fetchSchedule.ts"`).** pnpm's isolated store keeps `ofetch` out
of top-level `node_modules`, so Vite's import-analysis fails while transforming
`fetchSchedule.ts` — *before* `vi.mock('ofetch')` ever gets a chance to
intercept. `pnpm why ofetch` shows a single deduped `ofetch@1.5.1` across the
entire tree.

**Class D — broken rename (verified error text: `ReferenceError: currentPicks is
not defined`).** Commit `b2c8b96` ran a no-unused-vars autofix that renamed the
*declarations* and left the *usages* alone. The declarations are the wrong half
to carry the underscore, because these variables genuinely are used.

**Class E — Nuxt auto-import (verified error text: `ReferenceError: computed is
not defined` at `PickProgress.vue:17`).** `app/components/StandingsTable.vue`
already solves exactly this by importing `useId` explicitly from `'vue'` with a
comment explaining why. Match that pattern.
</diagnosis>
