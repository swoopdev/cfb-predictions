<task type="auto">
  <name>Task 1: Remove the tied-row band/border, lighten marker (b), and center the Rank column</name>
  <files>app/components/StandingsTable.vue</files>
  <action>
Three changes, all inside `app/components/StandingsTable.vue`.

**1. Remove the row-level tied treatment.** The `<tr>` currently binds a conditional class
array: a plain `'transition-colors'` plus, when `row.markerKind === 'b'`, a tied-row
band/border, otherwise a hover class. Replace this with one static class string applied to
every row unconditionally — the same `transition-colors` plus the same hover treatment
that non-tied rows already get — so tied and non-tied rows render identically at the row
level. Delete the `markerKind === 'b'` branch entirely; the `:class` binding can become a
plain `class` attribute since there is no longer a per-row conditional. Update the short
inline comment immediately above this binding (currently explaining the three-state rank
cell) to note that the row itself no longer carries any tie-related styling — the tie
signal now lives entirely in the rank cell/marker, per constraint 4's wording rule.

**2. Lighten `MARKER_B_CLASS`.** It currently uses a solid `bg-inverted`/`text-inverted`
fill — the strongest-contrast neutral pair in the palette. Replace it with a visually
lighter treatment that still reads as a distinct, clickable pill: swap the fill to
`bg-muted`, the text color to `text-toned`, and add a `ring ring-default` for definition
(matching the `ring ring-default` pattern already used on `StandingsSidebar.vue`'s panel).
Keep `rounded-full` (the shape that already distinguishes it from marker (a)'s `rounded`
square) and keep every other utility (`inline-flex min-w-6 justify-center px-1 text-sm
font-semibold tabular-nums`) unchanged. Do not touch `MARKER_A_CLASS` — its `bg-accented
text-default rounded` chip is the fixed point marker (b) must stay visually distinct from.

**3. Center the Rank column.** Two places carry the column's alignment: the `<th>` header
cell reading "Rank" in `<thead>`, and the single `<td>` in each row's `<tbody>` cell that
wraps both the button (marker) and the plain-number `<template>` branch. In both places,
change `text-left` to `text-center`, and change the asymmetric `pr-2` padding to symmetric
`px-2` so the centering is visually true (not skewed by one-sided padding). The button
inside the `<td>` is `inline-flex` (an inline-level box), so `text-center` on the parent
`<td>` centers it automatically — no change needed to the button's own classes for this.
  </action>
